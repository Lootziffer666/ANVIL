Was ist Anvil?

Anvil ist eine KI-native, agentische IDE — eine Werkbank für einen Entwickler (Christian Amine). Kein Showroom, kein Dashboard, kein App Store. Alles, was Anvil produziert, hat eine ID und eine Provenienz.

✅ Ist❌ Ist nicht
Eine Werkbank — Workspaces mit ModulenKein App Store
Ein Launchpad (The Forge)Kein Dashboard
Ein Output-System — alles mit IDKein Framework / Library
Ein KMP-Monorepo mit stabilen ContractsKein Mono-Lith

Zustands-Grammatik

Vier kanonische Zustände gelten für alles: Workspaces, Module, Runs, Artifacts.

Quality Guard

interface ModuleSlotContract {
    val id: ModuleId
    val version: SemVer
    val capabilities: Set<Capability>
    val requires: Set<Capability>
    suspend fun boot(ctx: ModuleContext): BootResult
    suspend fun handle(step: RunStep): StepResult
    fun qualityState(): QualityState   // Pflicht — nie hardcode STABLE
}

Triade der Reject-Tests (alle drei müssen bestehen):

  1. Quality Guard — QualityState ≥ DEGRADED für alle Module
  2. FLUBBER Acceptance Test — Output ist vom Mensch abnehmbar
  3. Räumliche Ordnung — Alle Dateien liegen im erwarteten Pfad

Acceptance-Kriterien für alle MVP-Gates. Drei MVP-Gates: Plan Gate, Diff Gate, Artifact Gate. Kill-Kriterien definiert. Triade der Reject-Tests.

Kill-Kriterien

Harte Kill-Kriterien (sofort FAILED)

  • Änderung außerhalb Workspace.rootPath — immer Exception, nie silent
  • PrivacyMode.LOCAL_ONLY + Cloud-Request — sofort BellowsExhaustedException
  • Modul ohne ModuleSlotContract-Implementierung
  • Zirkuläre Modul-Abhängigkeit (z.B. :core importiert :modules)
  • Donor-Code ohne Mapping in Transplant Map in aktive Pfade kopiert

Prozess-Kill-Kriterien (Gate nicht passierbar)

  • Commit ohne Gate-Referenz
  • PR ohne Definition-of-Done-Check
  • allWarningsAsErrors = true verletzt — kein Suppression erlaubt
  • Raw String als ID statt @JvmInline value class
  • Neues Modul ohne qualityState()-Implementierung

Donor-Disziplin

ANVIL nutzt externe Repos als Pattern-Donor, nicht als Code-Donor.

Donor-RepoPatternWas übernommen wirdWas nicht
kekegdsz/android-gradle-smart-build Git-Diff → Module-Map → BFS → TaskGraph-Pruning Algorithmus-Logik, KMP-Adaptation Groovy-Script direkt, Android-only Plugin-Detection
google/diff-match-patch Diff-Berechnung + Patch-Anzeige 1 Java-Datei (Apache 2.0), vendor-bar —
Donor-Disziplin-Regeln:
Kein blinder Code-Import. Kein Identity-Takeover (fremde Namen übernehmen). Pattern-Adoption only. Jeder Donor-Code braucht einen Eintrag in docs/provenance/.
